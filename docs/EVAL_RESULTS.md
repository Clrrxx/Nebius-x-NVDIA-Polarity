# Evaluation results

**Status: PENDING.** No real evaluation has been run yet. It needs the team's photo dataset from the real rig
and a `NEBIUS_API_KEY`. No accuracy number for Polarity exists until this file is regenerated by a real run, and
none may be quoted in the README, Devpost text or video before then.

How the numbers will be produced:

1. Capture at least 5 photos per (step, label) on the real rig, with slightly varied lighting:
   `python -m polarity capture --lab lab1 --step s3 --label E_LED_REVERSED` (Space saves raw + warped photos).
   Labels are `correct` or a common-error id from `labs/lab1.yaml`; for the power test also capture LED-off photos
   with `--label _baseline`.
2. Run `python -m polarity eval --dataset data/eval/lab1`. The full bench pipeline runs on every photo (board
   warp → quality gate → Nemotron Nano Omni → deterministic decision → second look), and this file is overwritten
   with the results plus `docs/eval_predictions.csv`.

Metrics reported: coverage (share not CAN'T TELL), selective accuracy (accuracy among checks that gave a verdict),
**false-pass rate** (wrong builds marked pass, the most important number), error-ID hit rate, CAN'T TELL rate per
step, latency p50/p95, cost per check and a confusion matrix, together with model IDs, the prompt hash and a
settings snapshot.

Decision gate: false-pass ≤ 5% and selective accuracy ≥ 85%. If it is not met, tune in this order and re-run,
recording each iteration below: (1) capture/lighting, (2) crop/zoom, (3) prompt wording, (4) thresholds,
(5) mark hard checks `allow_uncertain`.

`python -m polarity eval --mock` exercises the harness on synthetic images with canned answers. Its output goes
only to `data/eval_runs/` and is never evidence.
